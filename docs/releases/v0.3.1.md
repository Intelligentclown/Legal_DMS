# Release v0.3.1

## Release Version
0.3.1

## Release Date
2026-08-06

## Project Stage
Stage 2 — Database Architecture & Data Model (complete, tagged `v0.3.0` along with seven
post-Stage-2 framework additions and their QA review resolution — see Versioning Note below), plus
now **Stage 2.7 — GitHub Actions CI** ([ADR/0017](../../ADR/0017-github-actions-ci.md)). Stage 3
remains unscoped — see [Next Planned Release](#next-planned-release).

**Versioning note:** the `v0.3.0` tag was cut on the commit that already includes seven post-Stage-2
framework additions (Command Bus, Query Bus, Transaction Pipeline, Caching Abstraction, Module
Manifest Loader, Architecture Health Check, Performance Metrics Service) and their QA review
resolution — internally documented at the time under separate incrementing patch versions (0.3.1
through 0.3.8), none of which were ever tagged individually. **This release does not re-cover that
work** — it's already part of `v0.3.0`; see the root [`CHANGELOG.md`](../../CHANGELOG.md)'s
corrected `[0.3.0]` entry and [`docs/CHANGELOG.md`](../CHANGELOG.md) for its full detail. This
document covers only what's genuinely new since that tag.

## Summary

Two small, unrelated pieces of work landed since `v0.3.0`: a documentation-tooling addition (a
database migration template, already merged to `main` before this session started) and **Stage
2.7 — GitHub Actions CI**, three workflows validating every push and pull request. Neither is a
business-feature release — no schema change, no route change, no business logic. The CI plan was
reviewed and approved in two passes: an initial proposal (read all documentation, review actual
repo tooling, no code), then seven explicit project-owner decisions overriding several of that
plan's defaults. Every workflow command was verified by running it directly in this environment
before being written into YAML, including a full backend suite run (282/282, zero skipped) during
this release's own commit-prep pass. The one thing this release cannot yet confirm is a real
GitHub Actions run itself, since that requires a commit and push — a confirm-first action outside
this release's scope until explicitly approved.

## Major Features

None — this release is documentation-tooling and CI/tooling, not a feature release.

## Architectural Improvements

- **GitHub Actions CI** ([ADR/0017](../../ADR/0017-github-actions-ci.md)) — `.github/workflows/`
  gains `backend.yml` (ruff, black --check, `pytest tests/unit`, an application-import/boot smoke
  test — Python 3.14), `frontend.yml` (eslint, prettier --check, vitest — Node 24.13.1/npm
  11.11.1), `release.yml` (build verification only — compiles Electron TS + builds the frontend;
  **not** a packaging or deployment pipeline despite the name). All three trigger on push to
  `main`/`feature/**`/`hotfix/**`/`release/**` and on pull requests targeting `main`, with
  per-workflow `concurrency` cancellation and least-privilege `permissions: contents: read`.
  `engines` added to both `package.json` files (`node: >=24.13.1`, `npm: >=11.11.1`), raising the
  project's previously-undeclared "Node 20+" floor.
- No change to any backend port, repository, service, or route.

## Breaking Changes

None to application behavior. **Tooling-level:** the new `engines` field means `npm install`/`npm
ci` will emit an engine-mismatch warning (not a hard failure, by npm's default) for anyone on Node
<24.13.1 or npm <11.11.1.
