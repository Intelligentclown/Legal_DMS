## Summary

This release closes out a QA review of the seven post-Stage-2 framework additions
([docs/reviews/Stage_2_5_QA_Review.md](../reviews/Stage_2_5_QA_Review.md)), fixing its two
immediately-actionable findings (Q1/T20, Q8/T21), and then synchronizes the entire documentation
set to match. It is **not a feature release** — no business logic, no schema change, and no route
change shipped. Beyond the two code fixes, this release corrected a stale backend test count that
had drifted across six documents, fixed several docs that were up to two stages behind the actual
project state, and introduced two new standing documentation systems: the Architecture Scorecard
([docs/ArchitectureScorecard.md](../ArchitectureScorecard.md)) and this release notes system
(`docs/releases/`). All work in this release is documentation- and QA-fix-scoped; the two source
changes are both single-file, low-risk corrections to code that already existed.

## Bug Fixes

- **`TransactionPipelineBehavior.dispatch()` now rolls back on cancellation (T20, QA finding Q1).**
  `backend/src/app/infrastructure/commands/transaction_pipeline_behavior.py:47` previously caught
  `except Exception`, which does not catch `asyncio.CancelledError` (a `BaseException` subclass
  since Python 3.8) — a cancelled dispatch (client disconnect, request timeout, server shutdown
  grace period) skipped `rollback()` entirely and left the unit of work `_active=True`. Widened to
  `except BaseException`, with an inline comment explaining why, still re-raising after rollback so
  cancellation propagates correctly. Invisible in production today because `InMemoryUnitOfWork`
  backs no real resource; would have become a leaked-connection/held-lock risk the moment a
  resource-backed `UnitOfWork` was plugged in. Two new regression tests prove the fix:
  `test_dispatch_rolls_back_and_reraises_on_cancellation` and
  `test_dispatch_rolls_back_and_reraises_on_a_base_exception`.
- **Stale documentation "bugs" corrected** (see [Documentation Improvements](#documentation-improvements)
  below for the full list) — not source bugs, but worth listing here since at least one was a
  factual error a reader could act on incorrectly: `docs/API.md`'s `/api/v1/version` example
  response showed `"version": "0.1.0"`, but the endpoint actually returns `settings.app_version`,
  `"0.2.0"`.

## Technical Debt

Full detail in [IMPLEMENTATION_QUEUE.md](../../IMPLEMENTATION_QUEUE.md) and
[docs/ArchitectureScorecard.md](../ArchitectureScorecard.md) — summarized here, not duplicated:

- **One Critical/P0 item pending project-owner approval, not fixed in this release:** `get_db()`
  never commits — only `flush()`es — so a write can appear to succeed within a request and then
  vanish (finding F1). Part of the still-**unapproved** "Stage 2.5 — Architecture Hardening"
  backlog (T1–T18); this release did not touch it, since it's outside this release's QA-fix scope
  and awaiting explicit go-ahead.
- **Five QA findings remain open by design**, each gated on a dependency that doesn't exist yet:
  Q2/Q3/Q7 (transaction-pipeline correctness against a real, non-in-memory `UnitOfWork`;
  `Container.resolve()`'s thread-safety assumption; a `rollback()`-raises edge case), Q5 (module
  manifest loader's unrestricted dynamic import, gated on it being wired into `main.py`), Q9
  (`Container.resolve()`'s lack of async-factory support, gated on a real async-requiring
  implementation being proposed).
- **Two QA findings are accepted, ADR-documented trade-offs, not debt:** Q4 (bus implementations'
  structural duplication, [ADR/0011](../../ADR/0011-query-bus.md)), Q6 (`InMemoryCache`'s
  lazy-only TTL expiry, [ADR/0013](../../ADR/0013-caching-abstraction.md)).
- **The 107 integration tests have not been run against a live Postgres since before this
  release's fixes landed** — a verification gap this release discloses rather than papers over
  (see Known Issues above).
